# 阶段 4E-0：位图识别评测基线与标注契约

状态：独立验收通过，等待用户确认。

## 目标

在继续改尺寸、门窗和断线识别前，冻结真实户型图的标注格式和可重复评测入口，避免用合成矩形 fixture 推断真实图泛化能力。

## 标注格式

标注文件使用 `schema_version=stage-4e-annotation-v1`，至少包含：

- `asset_sha256`：原始位图 SHA-256；
- `pixel_size`：原始图像宽高；
- `rooms`：`id` 和像素坐标 `[x, y, width, height]`；
- `walls`：`id`、`axis`、`x`、`y`、`length`；
- `openings`：`id`、`host_wall_id`、`kind`、`offset`、`width`。

标注只描述人工确认的像素事实，不把比例尺或语义推断混入标注。加载时校验有限数、正尺寸、唯一 ID、墙轴和开口宿主引用。

## 当前评测指标

`evaluate_rooms` 对预测与真值房间做确定性一对一匹配，输出：

- 预测数、真值数、匹配数；
- 在指定 IoU 阈值下的 precision、recall 和 F1；
- 接受匹配的 mean IoU；
- 每个匹配的预测 ID、真值 ID、IoU 和是否达标。

首期默认房间 IoU 阈值为 `0.95`。墙体位置、开口召回、尺寸误差指标将在真实标注集建立后接入同一评测报告。

## 阶段门

1. 标注文档非法时在评测前失败，不产生误导性指标。
2. 相同预测和真值重复评测得到完全相同 JSON 结果。
3. 评测器不修改 SpatialModel、原始位图或 ingest artifact。
4. 独立验收通过后，冻结首批真实标注集，再进入尺寸线和门窗识别实现。
