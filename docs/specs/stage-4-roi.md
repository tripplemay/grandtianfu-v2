# 阶段 4 下一检查点：户型区域候选

## 目标

针对真实宣传页、带标题/尺寸链/品牌纹理的平面图，先从整张位图中提出一个或多个
“户型区域候选”（ROI），供人工选择或裁剪，再运行墙体与房间识别。ROI 是证据和
输入参数，不是自动确认的空间事实。

## 不变量

- 原图、原始 hash 和当前导入任务不可改变；ROI 坐标始终以规范化原图像素为基准。
- ROI 外的线、文字和装饰不进入该次几何识别，但仍保存在原图和 evidence manifest 中。
- 自动 ROI 只有 `candidate` 状态；未经过人工选择/裁剪，不能消除
  `partial_plan_requires_manual_trace`，也不能直接确认或进入 3D。
- 重新裁剪/重新识别生成新的 ingest identity，旧草稿和旧候选不可覆盖。
- 选出的 ROI 必须保留 bbox、算法版本、候选评分、原图 hash 和操作者动作记录。

## 最小阶段门

1. 对用户宣传页可以产生可解释的 ROI bbox 候选，而不是把整张页面作为线稿。
2. 合成海报 fixture 中，主户型 ROI 与标注 bbox IoU `>=0.90`；标题、logo、尺寸链
   不得进入主候选。该指标只验证区域提取，不代表墙体/房间识别精度。
3. 无法得到稳定 ROI 时返回结构化 `roi_required`，保留原图和候选证据，不生成可确认草稿。
4. 人工选择 ROI 后，识别坐标能映射回原图；原图、裁剪图、候选 overlay 与 manifest hash
   可互相追溯。
5. 真实图片必须至少能显示“局部候选 + 未覆盖区域 + 需人工处理”的原因，不能静默丢失
   左侧楼梯、客餐厅和其他房间。

## 暂不做

- 自动决定整屋房间拓扑；
- 用面积、标题中的建筑面积或 OCR 数字猜测比例；
- 通过降低最短线段阈值来掩盖家具、文字和尺寸链；
- 将 ROI 选择当成真实墙体/门窗校核；
- 在本检查点接入家具布局或照片级生成。
