# 阶段 2：2D 可编辑平面闭环

状态：实现中。此阶段对应用户确认的 2D 投影、编辑、保存、重载、revision 切换，不包含位图识别。

## 输入与展示

- 使用本仓手工 `orthogonal_v1` 模型，不依赖旧仓资产。
- 房间、merge 组、墙厚、开口和家具均从同一 SpatialModel 派生为 SVG。
- 所有数值控件以毫米编辑。视口平移/缩放/适配不得改动模型。
- 沿用阶段 1 家具变换约定：x/y 是旋转后 footprint 的最小坐标，90 度交换 width/depth；不在本阶段暗改为中心旋转。

## 编辑边界

- 家具支持数值位置、尺寸、高度、90 度朝向、房间归属、画布拖动、添加与删除。
- 墙体支持厚度/高度；开口支持宿主、偏移、宽高；房间支持名称及矩形宽高调整，显式同步边界墙。房间原点及影响共享墙的尺寸只读，本阶段不做拓扑级移动、拆墙或新建 merge 分组。
- 不支持本阶段的操作不显示假按钮。无自动布局、自动纠偏和位图导入。
- 每次有效操作保留撤销/重做；未保存离开或切版本必须确认丢弃。

## 保存与历史

- SQLite 仅作为本阶段本地工作台持久化，后续生产数据库另行决策。
- revision 行不可 UPDATE/DELETE。服务端通过事务分配递增 revision。
- 客户端必须提交期望的最新 revision/hash；并发旧写入返回 409，不覆盖。
- 普通保存形成 draft，显式人工确认形成 confirmed。任何修改不继承旧确认。
- 历史版本只读；恢复历史创建新 revision，不回滚或覆盖原行。
- 每次读取验证保存的 model/hash，坏数据不能静默替换为样例。

## 阶段门

1. 浏览器打开模型，修改家具后保存，刷新重载坐标/尺寸/ID 完全相同。
2. 切历史版本正确还原；恢复历史生成新 revision。
3. 墙/房间边界、开口和家具错误被后端拒绝，当前版本不变。
4. 保存时无权隐式移动家具；拒绝、取消、缩放及平移均不改变已保存模型。
5. 同一 JSON 保存/读取 canonical_hash 稳定；两个旧写入最多一个成功。
6. 桌面与移动端浏览器验证，截图和后端/前端自动测试记录。

边界墙要求覆盖房间各侧，不要求墙段长度恰好等于单个房间边长：共享墙可以跨越多个房间。此规则不代表完整的墙网连通或房间无重叠拓扑验收。

## 安全边界

服务只绑定 loopback，不带生产部署/公开访问/鉴权。无计费 AI 调用、无旧数据迁移。公网使用必须等待后续认证授权和生产化阶段。

工作台 API 还执行以下输入边界：

- `rooms` 和 `walls` 必须为非空数组；本阶段不接受空白模型（包括 `draft`）。
- JSON 中所有 number（包括未知扩展字段）必须为有限值，且绝对值不超过 `1_000_000_000`。该全局上限用于防止 2D/SVG 派生时坐标加法和尺寸分配产生极值。
- 该上限不是 3D 净空或完整拓扑验证。家具高度、墙体相邻关系、merge 组连通性、门洞/通道净空等属于后续 3D 场景与拓扑阶段；当前仅执行 SpatialModel 的基础引用、边界和 2D 碰撞校验。
