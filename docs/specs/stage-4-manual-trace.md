# 阶段 4C1：自由 ROI 与人工多房间描图

状态：building。用户于 2026-09-07 确认继续。完成独立验收后暂停，不进入阶段 5。

## 范围

- 在归一化整图上拖框或数值输入自由 ROI；自动候选仅为可修改的起点。
- 自动裁剪识别失败后保留图片、ROI 与错误，允许直接人工描图。
- 描图支持 1 至 64 个矩形房间、名称/类型、像素坐标精确编辑、删除、撤销和重做。
- 从人工房间生成正交墙图；同线相接或重叠的边界去重为共享墙，不跨空白间隙合并。
- 用户明确填写墙厚和墙高；比例沿用当前 ingest，不猜测尺寸、门窗或家具。

## 契约

`POST /api/ingests/{id}/trace` 严格接收：

```json
{
  "expected_source_sha256": "parent source hash",
  "bbox": [0, 0, 400, 300],
  "rooms": [{"name": "Living", "kind": "living", "rect": [40, 30, 160, 240]}],
  "wall_thickness_mm": 200,
  "wall_height_mm": 2800
}
```

- bbox 为整数；房间 rect 允许有限小数，均为归一化原始整图像素，必须位于 bbox 内。
- source hash 错配为 409；非法输入、重叠房间、超量或不支持的拓扑为 422。
- 新 trace identity 绑定父 ingest、父源 hash、输入参数和算法版本；重复请求幂等。
- 新任务保存原图、归一化图、模型和 manifest；父任务、父 revisions、原图不可覆盖。
- 每个对象记录人工来源及尺寸换算证据。源图坐标到 mm 只进行显式比例换算。
- 派生任务重复裁剪继续采用整图坐标，候选/线段/OCR/几何及其 hash 指向一致。

## 阶段门

- 桌面/移动端自由 ROI、候选修改、失败后描图路径可用；非法编辑不能提交。
- 相邻、T 形相接和分离房间的墙图覆盖、去重与原点映射可核验。
- 后端拒绝重叠、非法数字、越界、陈旧源 hash 和工件篡改；不产生半发布任务。
- 真实宣传图可在原图上人工生成可追溯的多房间草稿；不宣称自动全屋识别通过。
- 独立 evaluator 按实物验收并原样写入报告。

## 保留的阻断

新草稿始终带 `manual_trace_requires_topology_review`。本检查点不推断门窗、房间连通性或
merge 分组；人工描图不能直接确认或进入 3D。后续 4C2 必须实现这些对象的编辑和
可执行拓扑校核，再讨论解除门禁。不得仅靠勾选“完整”清除硬阻断。
