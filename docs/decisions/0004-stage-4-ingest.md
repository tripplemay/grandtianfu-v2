# ADR 0004：阶段 4 位图导入与人工确认边界

## 状态

Accepted，2026-09-07。

实施补充：本轮强制用户显式给出 `mm_per_pixel`，缺省直接拒绝；不生成单位为 mm
但数值实际为像素的草稿。完整阶段门仍未通过，当前闭环范围见
`../specs/stage-4-integration.md`，未完成的 OCR 尺寸关联与真实样本门窗精度不豁免。

## 背景

阶段 1-3 已建立以 `SpatialModel v2` 为唯一事实源的正交几何、2D 工作台和
确定性 CPU 3D 渲染。下一步需要接收真实用户的平面图，但未经核验的 CV/OCR
结果不能直接驱动家具布局或渲染，否则会把像素误差伪装成工程尺寸。

输入类型越多，坐标校准、页面语义和失败模式越多。当前目标是验证“位图 ->
可审查草稿”的闭环，因此必须限制首期边界并保留全部证据。

## 决策

1. 首期同时支持 PNG 和 JPEG/JPG；按文件签名验证 MIME，统一解码为规范化 PNG。
   PDF、CAD/DXF/IFC 和透视照片不在首期范围，明确拒绝而非近似导入。
2. 采用不可变原始 asset + 可复现预处理 + 候选识别 + draft SpatialModel 的
   四段流水线。每段输出带 hash 的 artifact 和算法参数。
3. 首期 profile 只生成 `orthogonal_v1`：水平/垂直墙、矩形房间和 merge 候选。
   任何斜墙、自由多边形、断边界、房间重叠或无法关联宿主的门窗都进入人工处理，
   不做静默正交吸附或“最佳猜测”补全。
4. 尺寸来源采用“用户比例尺 > OCR 尺寸标注 > 比例尺图例 > 像素距离”的优先级。
   未知比例只能产生 draft，不得确认。
5. 所有自动推断对象必须包含 `provenance`、`confidence`、证据 bbox 和
   `needs_review`。低于 0.90 或涉及拓扑/尺度的低置信度对象阻断确认。
6. 复用现有 2D 工作台进行叠加校核和修正。确认只能通过现有 revision/CAS 机制
   生成新的 `confirmed` revision；识别任务本身不调用 3D、布局求解或 LLM。
7. 预处理和识别在独立 CPU worker 中执行，API 进程不运行长任务；任务由输入 hash、
   算法版本和参数 hash 幂等寻址。原始文件、失败日志和中间候选均保留。

## 取舍

- **为何不是 PDF/CAD**：PDF 可能包含多页、旋转页面和混合栅格/矢量层；CAD/IFC
  需要图层、单位和块语义映射。它们适合在位图闭环和人工审核稳定后单独设计，
  现在加入会掩盖基础比例和拓扑问题。
- **为何同时支持 PNG/JPEG**：二者都能通过同一像素预处理路径，覆盖导出图和用户
  截图；JPEG 的压缩噪声必须进入置信度与质量报告，而不是改变几何契约。
- **为何只输出 draft**：墙体、开口和比例一旦错误，会在 3D 和家具布局中放大；
  人工确认是事实边界，不是可选的 UI 步骤。
- **为何 CPU worker**：与阶段 3 的部署约束一致，保证可复现、可限时和可观测；
  后续可替换 CV 模型，但不能改变 artifact 和确认协议。

## 后果

- `SpatialModel` 继续是唯一事实源，位图、预处理图和候选 JSON 都是可追溯派生物。
- 首期用户会遇到明确的人工确认和不支持输入提示，但不会得到无法解释的“精确”结果。
- 需要增加 ingest manifest、候选证据模型、对象级警告和审核清单；这些数据必须
  随 revision 保存，供阶段 5/6 的几何验收使用。
- 阶段 4 通过不代表自动识别可无人值守；只有确认后的 revision 才能进入后续阶段。

## 退出与复审条件

若固定 fixture 无法达到规格中的墙/房间/门窗/尺寸指标，或任一失败输入会绕过
人工门禁，则阶段 4 不得进入家具布局。PDF/CAD、透视照片和自动确认必须以新的
ADR 单独评审，不能通过扩大本 ADR 的解释范围接入。
